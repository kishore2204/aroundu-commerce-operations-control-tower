## What's tested, per module

- **S1**: full CRUD + validation for State/City/Zone/UserAccount/OperationsManager/LocationManager, JWT issuance and validation (`JwtServiceTest`), the `/api/v1/auth/login` controller (`AuthControllerTest`), the `/api/v1/users/me` controller (`CurrentUserControllerTest`), account-status patching, and a Spring-Security-integration test (`SecurityIntegrationTest`) proving role-gated endpoints actually reject/accept the right roles end-to-end through a real `MockMvc` + Spring Security filter chain.
- **S2**: full CRUD across Retailer/FleetOwner/VerificationDocument/VerificationQueue at both the controller (`@DataJpaTest`-adjacent MockMvc) and service layers, plus the new reviewer-assignment workflow.
- **S3**: (see note above for current status) product/cart/wishlist/checkout/review business logic including stock validation, default-address invariants, SKU uniqueness, and Feign-mocked cross-service checks.
- **S4**: the full `Trip` state machine (`PLANNED→ASSIGNED→IN_PROGRESS→COMPLETED`/`CANCELLED`), the logistics cost-estimation engine, order/order-item creation with Feign-mocked S3 product snapshots, and the new order-tracking + trip-lifecycle-action endpoints.
- **S5**: driver/vehicle/assignment/expense creation with Feign-mocked S2 eligibility checks, availability filtering, approve/reject-with-self-approval-block, and the new fleet-owner expense filter.
- **S6**: all 8 services' create/update/delete/not-found paths including the reflection-based update-re-validates behavior specific to this codebase, and the new notification read-tracking endpoints.
- **API Gateway**: the full role × route-group authorization matrix (see `architecture.md` for the rule table this is testing).

## Test types used

- **JUnit 5** everywhere.
- **Mockito** for all service-layer unit tests (repositories and Feign clients mocked).
- **MockMvc** for controller-layer tests where present (S1's `SecurityIntegrationTest`, S2's controller test suite, S5's new `FleetExpenseControllerTest`).
- **H2** (in-memory) backs every service's own `@SpringBootTest`/context-load test and any `@DataJpaTest`-style repository test.
- No integration test spans more than one service's own process — cross-service interaction is tested via mocked Feign clients at the unit level, not live inter-service calls in the automated suite. (A *manual*, live, multi-service run was performed once in this session's prior pass — see `architecture.md` §3-4 — but that is not part of the repeatable automated test suite.)

## Known test-coverage gaps (honest, not padded)

- S2's low branch coverage (20.8%) reflects that its `dao` package (thin pass-through wrappers around the repositories) and Feign `client` package have 0% coverage — the service-layer tests mock the DAO interfaces directly rather than exercising the pass-through implementations, and no test exercises a live/mocked Feign failure path for `LocationManagerClient`.
- No module has a test that deliberately exercises a Feign timeout/connection-failure scenario end-to-end (all Feign interactions in tests use Mockito-returned success or explicit exception-throwing stubs, not a simulated network failure) — acceptable for unit-level coverage, but real resilience behavior (timeouts, retries, circuit-breaking) is unverified.
- Controller-layer coverage is uneven — S1 and S2 have real MockMvc controller tests; S3/S4/S6 are primarily service-layer tests with thin/delegating controllers presumed correct by inspection rather than independently tested; S5 gained its first controller test in this pass (`FleetExpenseControllerTest`) but the other three S5 controllers remain untested at that layer.
